# 푸시마다 저장소가 성한지 검사하게 하다

## 무엇이 바뀌었나

`.github/workflows/check.yml`을 두었다. 푸시와 PR마다 Python 3.10·3.12에서 세 가지를 본다.

1. `saemaul_mcp_server.py --check` — 출처·문서·검색어 사전이 서로 맞는가
2. `tests/smoke_test.py` — 도구와 프롬프트가 실제로 뜨는가
3. 판독문을 다시 생성해 커밋된 생성물과 같은가

## 왜 바꿨나

사용자가 "push하면 알아서 반영되는가"를 물었다. 저장소에 CI도 git 훅도 없었다. 검사를 자동화하면
로컬에서 테스트를 깜빡해도 깨진 커밋이 드러난다.

셋째 검사가 이것을 넣은 진짜 이유다. 판독문에 줄을 하나 더하면 그 뒤 단락 id(`p001`…)가 전부
밀리고 `meta.yaml`의 `cross_references`가 엉뚱한 대목을 가리킨다. 이 사고는 조용히 번지고
사람 눈으로 잡기 어렵다. 넣기 전에 `build_document.py`가 결정적인지(같은 입력 → 같은 출력)를
먼저 확인했다. 비결정적이었다면 이 검사는 거짓 실패를 냈을 것이다.

### 고르지 않은 것

커밋 메시지를 긁어 CHANGELOG를 자동 생성하는 방식은 쓰지 않았다. "협동과 분업의 등식을 걷어냈다,
왜냐하면 결론으로 가는 다리가 사라지기 때문이다" 같은 판단 근거는 커밋 제목에서 뽑아낼 수 없다.
자동 생성으로 바꾸면 기록이 파일 목록 나열로 떨어진다.

## 바꾼 파일

- `.github/workflows/check.yml` — 신규
- `docs/maintenance.md` — 자동으로 도는 검사 절 추가. CI는 알려 줄 뿐 고치지 않음을 명시

## 확인한 것

- YAML 파싱 — 잡 1개, 스텝 6개
- 세 단계를 CI와 같은 순서로 로컬에서 실행 — 모두 통과
- `build_document.py` 재생성 후 `git diff` — 변화 없음(결정적)

## 짝 문서

`docs/maintenance.md`에 기록했다.

## 되돌리려면

`.github/workflows/check.yml`을 지운다. 다른 것은 영향받지 않는다.
